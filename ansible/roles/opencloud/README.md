# OpenCloud

OpenCloud is a cloud storage solution. Accounts are automatically provisioned
via Authelia.

Collabora Online provides an online office suite integrated with OpenCloud. For
security reasons Collabora runs under its own user.

Radicale provides CardDAV and CalDAV service integrated with OpenCloud. Create an
app token for Radicale in OpenCloud and connect for example with DAVx5 (supports
mTLS).

## Upgrades

Upgrade guide: https://docs.opencloud.eu/docs/admin/maintenance/upgrade/upgrade-guide

* run `opencloud init --diff` in a temporary container with the config directory mounted
* check for patches to apply and apply them

## Architecture

### Collabora integration

Since Collabora can process potentially malicous files imported by users it is
confined to its own user. This prevents Collabora from having access to
OpenCloud's internal ports and services; while this could have been achieved
with kicking it out of OpenCloud's pod having a separate user also guards against
container escape and a compromised Collabora gaining access to OpenCloud's
credentials as well as internal services.

The host's ports (typically 9980 and 9200) on the loopback interface are used
where possible to enable communication between OpenCloud and Collabora to avoid
the extra hop via the reverse proxy (the only other party that could read the
traffic on those ports anyways).

## Configuration

### Authelia OIDC Integration

OpenCloud is configured to expect Authelia to provide the `opencloud_scope`.
This scope contains claims for `opencloud_role` (one of `opencloudAdmin`,
`opencloudUser`, `opencloudGuest`) and `opencloud_groups` (list of group names
of your choice). The `opencloud_role` must be defined in Authelia's user database under `extra`, e.g.

```
users:
  my_user:
    password: ...
    displayname: ...
    email: ...
    extra:
      opencloud_role: opencloudUser
      opencloud_groups: [my-group, other-group]
```

### OpenCloud

* https://docs.opencloud.eu/docs/admin/
* https://docs.opencloud.eu/docs/admin/configuration/authentication-and-user-management/external-idp
* https://www.authelia.com/integration/openid-connect/clients/opencloud/

OpenCloud does not require a shared secret with Authelia as it is configured as
a public client and will automatically generate all its internal secrets on
first startup.

The only thing needed to configure is the mTLS certificate:

* `opencloud_root_ca`: path to mTLS root CA certificate to guard OpenCloud

### Collabora Online

* https://sdk.collaboraonline.com/contents.html

To secure the admin endpoint `/browser/dist/admin/admin.html` an admin user name
and password are required.

Required configuration parameters:

* `opencloud_collabora_admin_user`: admin user name
* `opencloud_collabora_admin_password`: admin password

### Radicale

No configuration parameters needed.

Configuration same as in OpenCloud docker-compose setup (except Radicale
listening only on port 127.0.0.1)

## Storage Layout

The user space storage layout of OpenCloud is set to
`{preferred_username}-{internal uid}`; the `preferred_username` is provided by
Authelia (and cannot be changed by the users themselves), the internal uid is
generated by OpenCloud itself and ensures uniqueness. This choice is deliberate
to make the user folders identifyable more easily in case of required
administrative intervention such as data migration.
